Great question 👍 Let’s go step by step on how to implement Redis Cache in Spring Boot with explanations.

Redis is often used as a cache in Spring Boot because it’s fast (in-memory), supports persistence, and integrates nicely with Spring’s caching abstraction.

🔹 Steps to Implement Redis Cache in Spring Boot
1. Add Dependencies

If you’re using Maven, include:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>

<!-- Optional: For Redis connection pooling -->
<dependency>
    <groupId>io.lettuce</groupId>
    <artifactId>lettuce-core</artifactId>
</dependency>


📌 Explanation:

spring-boot-starter-data-redis → Integrates Redis into Spring.

spring-boot-starter-cache → Enables Spring’s caching abstraction.

lettuce-core → Redis client library (default in Spring Boot).

2. Enable Caching in Spring Boot

In your main Spring Boot application class:

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cache.annotation.EnableCaching;

@SpringBootApplication
@EnableCaching   // Enable Spring’s caching abstraction
public class RedisCacheApplication {
    public static void main(String[] args) {
        SpringApplication.run(RedisCacheApplication.class, args);
    }
}


📌 Explanation:
@EnableCaching tells Spring Boot to look for caching annotations (@Cacheable, @CachePut, @CacheEvict) and apply them.

3. Configure Redis in application.yml
spring:
  cache:
    type: redis
  data:
    redis:
      host: localhost
      port: 6379
      password: ""   # If no password set
      timeout: 60000


📌 Explanation:

cache.type=redis → tells Spring to use Redis as cache provider.

Redis connection details are provided here.

4. Use Caching Annotations
Example: Service Layer with Redis Caching
import org.springframework.cache.annotation.Cacheable;
import org.springframework.cache.annotation.CacheEvict;
import org.springframework.cache.annotation.CachePut;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.Map;

@Service
public class UserService {

    private static final Map<Integer, String> DB = new HashMap<>();

    static {
        DB.put(1, "John");
        DB.put(2, "Alice");
        DB.put(3, "Bob");
    }

    // Store result in Redis cache
    @Cacheable(value = "users", key = "#id")
    public String getUserById(int id) {
        System.out.println("Fetching from DB for id: " + id);
        return DB.get(id);
    }

    // Update cache when data changes
    @CachePut(value = "users", key = "#id")
    public String updateUser(int id, String name) {
        System.out.println("Updating DB and cache for id: " + id);
        DB.put(id, name);
        return name;
    }

    // Remove entry from cache
    @CacheEvict(value = "users", key = "#id")
    public void deleteUser(int id) {
        System.out.println("Deleting from DB and cache for id: " + id);
        DB.remove(id);
    }
}


📌 Explanation of annotations:

@Cacheable → Checks if result is in Redis cache. If yes → return cached value; if not → execute method & store result in Redis.

@CachePut → Always executes method and updates cache.

@CacheEvict → Removes data from cache (useful when deleting/updating records).

5. Testing the Flow
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

@Component
public class CacheTestRunner implements CommandLineRunner {

    private final UserService userService;

    public CacheTestRunner(UserService userService) {
        this.userService = userService;
    }

    @Override
    public void run(String... args) {
        System.out.println(userService.getUserById(1)); // Fetch from DB
        System.out.println(userService.getUserById(1)); // Fetch from Redis cache
        userService.updateUser(1, "Mike");             // Update DB + cache
        System.out.println(userService.getUserById(1)); // Fetch updated from cache
        userService.deleteUser(1);                     // Remove from cache
        System.out.println(userService.getUserById(1)); // Fetch from DB again
    }
}

John

null

🔹 Summary

Dependencies → Add Redis + Cache starter.

Enable caching → @EnableCaching.

Configure Redis → application.yml.

Use Annotations:

@Cacheable → Fetch & cache result.

@CachePut → Update cache.

@CacheEvict → Remove cache.

Let’s now look at implementing Redis cache without using annotations (i.e., not relying on @Cacheable, @CacheEvict, etc.). Instead, we’ll use Spring’s RedisTemplate directly to interact with Redis.

This approach gives you more control because you manually put/get/remove values from Redis.

🔹 Steps to Implement Redis Cache using RedisTemplate
1. Add Dependencies

(same as annotation-based approach)

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

<dependency>
    <groupId>io.lettuce</groupId>
    <artifactId>lettuce-core</artifactId>
</dependency>

2. Configure Redis in application.yml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      password: ""   # if no password set
      timeout: 60000

3. Define Redis Configuration

By default, Spring Boot auto-configures a RedisTemplate<String, Object>,
but often we create our own with proper serializers.

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.GenericJackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.StringRedisSerializer;

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory connectionFactory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);

        // Use String serializer for keys
        template.setKeySerializer(new StringRedisSerializer());

        // Use JSON serializer for values
        template.setValueSerializer(new GenericJackson2JsonRedisSerializer());

        return template;
    }
}


📌 Explanation:

KeySerializer → ensures Redis keys are stored as plain strings.

ValueSerializer → stores objects in JSON format, not Java serialization (which is less readable).

4. Service Class Using RedisTemplate

Example: Store and retrieve User objects from Redis.

Define a User model:
import java.io.Serializable;

public class User implements Serializable {
    private int id;
    private String name;

    public User() {}
    public User(int id, String name) {
        this.id = id;
        this.name = name;
    }

    // getters & setters
    public int getId() { return id; }
    public void setId(int id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

Service Layer:
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.stereotype.Service;

import java.time.Duration;

@Service
public class UserCacheService {

    private static final String CACHE_KEY = "USER_";
    private final RedisTemplate<String, Object> redisTemplate;

    public UserCacheService(RedisTemplate<String, Object> redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    // Save user in Redis with TTL
    public void saveUser(User user) {
        String key = CACHE_KEY + user.getId();
        redisTemplate.opsForValue().set(key, user, Duration.ofMinutes(5)); // cache for 5 minutes
        System.out.println("User saved in Redis with key: " + key);
    }

    // Get user from Redis
    public User getUser(int id) {
        String key = CACHE_KEY + id;
        return (User) redisTemplate.opsForValue().get(key);
    }

    // Delete user from Redis
    public void deleteUser(int id) {
        String key = CACHE_KEY + id;
        redisTemplate.delete(key);
        System.out.println("User deleted from Redis with key: " + key);
    }
}


📌 Explanation:

opsForValue() → used for simple key-value operations.

set(key, value, Duration) → stores data in Redis with TTL (time-to-live).

get(key) → fetches cached data.

delete(key) → removes data from cache.

5. Testing the Flow
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

@Component
public class RedisTemplateTestRunner implements CommandLineRunner {

    private final UserCacheService userCacheService;

    public RedisTemplateTestRunner(UserCacheService userCacheService) {
        this.userCacheService = userCacheService;
    }

    @Override
    public void run(String... args) {
        User user = new User(1, "John");
        userCacheService.saveUser(user);

        User cachedUser = userCacheService.getUser(1);
        System.out.println("Fetched from Redis: " + cachedUser.getName());

        userCacheService.deleteUser(1);
        System.out.println("After deletion: " + userCacheService.getUser(1)); // should be null
    }
}

User deleted from Redis with key: USER_1
After deletion: null

🔹 Comparison: Annotations vs RedisTemplate
Feature	Annotation-based (@Cacheable)	Manual (RedisTemplate)
Ease of Use	Very easy (just add annotations)	More boilerplate code
Flexibility	Limited (Spring manages cache)	Full control over cache operations
Use Case	Standard CRUD caching	Advanced caching logic (e.g., custom TTL, complex keys, hash structures)
